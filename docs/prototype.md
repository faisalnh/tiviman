# Development

## Toolchain

| Item | Version |
| --- | --- |
| JDK | 17 or newer |
| Gradle (wrapper) | 8.9 |
| Android Gradle Plugin | 8.7.3 |
| Kotlin | 2.0.21 |
| SDK | compile 35, target 34, minimum 23 |
| Media3 | 1.5.1 |

Android Studio isn't required. Dependencies come from Google's Maven repository and Maven Central.

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n faisalnh.tiviman/faisalnh.tiviman.MainActivity
```

Use an Android TV emulator (API 34, 1920 × 1080 is the reference setup) or a test device. Only install, clear, or uninstall `faisalnh.tiviman` and its test package; never touch other apps on the device.

## Sample data

Without a playlist, Tiviman shows twelve invented channels with invented programmes, all playing the same short original test clip, `app/src/main/assets/fixture.mp4`. `scripts/generate-fixture.swift` generated it with macOS AVFoundation and refuses to overwrite an existing file.

## Code layout

All code is in `app/src/main/java/faisalnh/tiviman/`. Views are native Android views; there's no Compose or Leanback library.

| Area | Main files |
| --- | --- |
| Guide and player | `MainActivity`, `GuideState`, `GuideRows`, `FullscreenChrome`, `PlayerToolbar` |
| Sources | `Playlist` (M3U), `Providers` (Xtream, Stalker, downloads), `PlaylistStore` (encrypted storage) |
| Guide data | `Epg`, `EpgRefresh`, `EpgActivity`, `EpgBrowserActivity` |
| Settings | `SettingsActivity`, `QuickSettings`, `SettingsMenu`, `PlaylistsActivity`, `PlaylistActivity` |
| Playback tools | `TrackControls`, `DisplayMode`, `SleepTimer`, `AudioDelay`, `AdvancedPlaybackActivity` |
| Visual system | `GlassTokens`, `GlassMaterial`, `GlassDialogs`, `GlassPage`, `TvTypography` |
| Privacy | `CapturePolicy` (`FLAG_SECURE`) |

## Tests

**JVM tests** in `app/src/test/` cover navigation state, parsers, guide geometry, matching, and timers. They need no device:

```sh
./gradlew :app:testDebugUnitTest
```

**On-device checks** in `app/src/androidTest/` use a custom platform instrumentation runner, `PrototypeChecks`, not AndroidJUnitRunner. They use synthetic data and local loopback servers, and refuse to run when a real playlist is saved. Don't bypass that guard.

```sh
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w faisalnh.tiviman.test/faisalnh.tiviman.PrototypeChecks
```

A pass prints `PASS` and `INSTRUMENTATION_CODE: -1`; a zero exit code from adb alone doesn't mean the checks passed. The default run needs a fresh install.

Add `-e <suite> true` to run one suite instead:

| Suite | Covers |
| --- | --- |
| `isolatedTools` | Full player regression: tracks, retry, quick switching, Favorites, picture-in-picture, guide import |
| `playlist`, `providers` | M3U import, Xtream and Stalker against synthetic servers |
| `multiPlaylist`, `allPlaylistsTools` | Multiple playlists and the combined browser |
| `epgRefresh`, `epgRefreshFeedback`, `epgBrowserTools` | Guide refresh, search, and mapping |
| `trackControls`, `playerMenus`, `advancedTools`, `audioDelayTools` | Player toolbar and tools |
| `playlistLabels`, `epgBrowserLabels`, `fontScale`, `fullscreenContrast` | Labels, large fonts, and contrast |
| `designCapture` | Synthetic screenshots for design review |

A few other suites in `PrototypeChecks.kt` (`privateProvider`, `savedNavigation`, `refreshSavedXtream`, `diagnoseSavedEpg`, `alternativeEpg`, `addAlternativePlaylist`) work with a saved real account or locally supplied files. Don't run them as part of normal testing.

**Smoke test:** `scripts/smoke-prototype.py` sends remote keys to a freshly launched app on `emulator-5554` and checks the UI hierarchy. It stops if Tiviman isn't in the foreground. Edit the `ADB` path at the top for your machine.

## UI captures

`scripts/capture-ui.py` saves a screenshot and UI hierarchy of the running emulator, optionally after sending keys:

```sh
python3 scripts/capture-ui.py example DPAD_LEFT
```

Output goes to `private/`, which git ignores. Captures taken with a real playlist can contain private metadata, so review them before sharing anything.

## Launch screen

While the saved playlist loads, `MainActivity` shows the wordmark (`R.drawable.tiviman_wordmark`) 300 px wide, centred on `#101216`. It pulses between full and 55% opacity, stays at least 600 ms (`SplashTiming.kt`), then fades out over 200 ms. Pulse and fade are skipped when animations are turned off. `Theme.Tiviman.Launch` shows a static wordmark before the app draws; on Android 12+ the system splash uses the canvas colour with a transparent icon.
